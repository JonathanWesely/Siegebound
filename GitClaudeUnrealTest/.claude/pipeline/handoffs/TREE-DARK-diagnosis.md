## VERDICT — (b), a LOD / geometry effect. The normal maps are exonerated.

The near-black faceted fronds are **not** the shipped LOD0 of the tree. They are a **decimated LOD** of a
leaf-card canopy. A shading fault cannot change a **silhouette**; only a geometry swap can — and the
silhouette in `TASK-1085-SIMULATE-lane.png` changes continuously with distance (fine leafy canopy far →
coarse triangular slabs near) on **one and only one tree asset family**. That is a geometry swap.

Corroborated live, right now, post-`e37c899`: `CaptureAssetImage("/Game/Tree_Pack_1/Meches/Mobile_Tree_1/SM-Mobile_Tree_1")`
renders a **bright yellow birch** with the D1 normal maps in place (saved:
`scratchpad/live_SM-Mobile_Tree_1.png`). The correct-looking tree is LOD0 — and **LOD0's screen-size
threshold is 2.0**, i.e. the tree must project larger than 2× the viewport height before LOD0 is used.
In a match that never happens, so **LOD0 is effectively unreachable and no instance ever renders it.**

## ② The LOD answer

`SM-Mobile_Tree_1` (representative; `_7` matches):

| | value |
|---|---|
| `LODGroup` | **`Foliage`** |
| LOD count | 5 (LOD0 + 4, generated by TASK-289b `generate_lods([0.5,0.25,0.125,0.0625])`, 2026-07-24) |
| Screen-size thresholds | **`[2.0, 0.1191, 0.0263, 0.001447, 0.001237]`** |
| Triangles per LOD | 2458 / 1228 / 615 / 308 / 154 |
| Material slots | `["Trunk","Leaf"]` — same slots on every LOD, **no billboard, no slot swap** |
| Placement | `ASiegeBattlefieldScatter` HISM, `scaleRange 0.8–1.2`, `overrideMaterial None`, uniform scale, yaw-only (no negative scale) |

- **The far LODs use the same materials as LOD0.** So the near/far split is *not* a billboard or a
  material-slot difference — that sub-hypothesis is dead.
- **It is a geometry difference.** LOD0's threshold `2.0` (vs `1.0` on the rocks, which render fine) means
  LOD0 is out of reach at any playable distance; every visible tree is LOD1 or coarser. LOD1 is a **50 %
  triangle reduction of a leaf-CARD canopy**, which merges cards into large triangles with collapsed UVs —
  producing exactly what the pixels show: big flat facets, no leaf texture anywhere on a huge on-screen
  area, and an opacity mask that no longer cuts a leaf shape, so each card reads as a solid near-black slab.
- **Why far looks fine:** the same wreckage at LOD3/LOD4 is sub-pixel; the mips average to green and it
  reads as a normal distant tree. The trees that genuinely look right in the frame (light yellow, fine
  canopy, including the branch at the very top-right *closest* to camera) are the **15 hand-placed
  `StaticMeshActor` trees**, not scatter instances.
