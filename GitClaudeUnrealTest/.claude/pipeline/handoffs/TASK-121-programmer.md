## Flagged decisions for QA
1. **"Actor under crosshair / nearest enemy" resolution (ApplyTestDamage).** On a LOCKED desktop there is no cursor, so the "crosshair" = the camera-forward line trace (`GetPlayerViewPoint` + `ECC_Visibility`, the controller's cursor-trace channel), ignoring the controlled pawn. If that hits an `ITeamAgent` actor → that is the target (friend OR foe — a debug tool damages what you point at). Otherwise → **nearest alive enemy** (`ITeamAgent` whose team ≠ the local team, measured from the pawn/view location). The nearest-enemy branch is the deterministic locked-desktop path and reliably drives the ENEMY castle HP + overhead bars (large static meshes reliably block Visibility; summoned-unit capsules may not, so units are best reached via the fallback). Verdict for QA: is "crosshair may hit a friendly" acceptable for a dev cheat? I ruled yes.
2. **World-damage instigator choice (ApplyTestDamage).** I pass `EventInstigator = nullptr` AND `DamageCauser = nullptr`, so `ACastle::TryGetInstigatorTeam` / `ASummonedUnit::TryGetDamageTeam` return false → the hit is treated as **world damage** and applies regardless of the target's team (bypasses no-friendly-fire immunity), at base `UDamageType` (100%, no Siege/Projectile/Spell fortification scaling). This is deliberate: a debug tool must be able to damage either side's castle/units. Confirmed against Castle.cpp:129-142 and SummonedUnit.cpp:1570-1634.
3. **SummonTestUnit is UNIT-only, Count = 1.** It composes `BP_Unit_<CardID>` and requires the class be an `ASummonedUnit`; a Building/Spell CardID has no `BP_Unit_` class and is refused with a log (no bespoke building spawn — the bot's building path `SpawnBotCardActor` is `private`, and the shared public entry is unit-only). It spawns ONE unit (not the row's SwarmCount) — call again for a swarm. It does NOT read DT_Cards (no dependency) — the composed-path + `IsChildOf(ASummonedUnit)` check is the whole gate.
4. **Spawn location (SummonTestUnit).** Ground point = the crosshair trace `ImpactPoint` (a true ground/surface point → correct for `SpawnUnitSwarm`'s capsule lift). Fallbacks: controlled-pawn location, then view-forward point. In the arena the forward trace essentially always hits ground, so the fallbacks are defensive only.
