Incident — files I destroyed during this audit

While dry-running the revert checks I ran a command whose && chain broke: the throwaway worktree was never created, so the cleanup statements after it executed against the real working tree — git reset --hard HEAD and git clean -fd. This was my error, not a pipeline fault.

  • LOSTThe in-engine verify screenshots — all .claude/pipeline/handoffs/TASK-3NN-verify-<Unit>-{tight,threequarter,wide,feet}.png. They were untracked and not ignored, so git clean -fd deleted them permanently. They were never committed, so Git cannot restore them. That is why the "after" columns on this page are the Blender/Cycles pipeline renders rather than the in-engine shots — those renders survived only because Tools/ArtPipeline/Cache/ is gitignored and clean -fd skips ignored files.
  • LOSTUncommitted edits to TASKBOARD.md — the file now matches HEAD exactly. The manager was writing the board at the time, so its in-progress work needs redoing.
  • INTACTAll 12 commits and origin/main. HEAD never moved — the reflog shows reset: moving to 6bd1cee, the same commit — and nothing was pushed.
  • INTACTCONVENTIONS.md, BP_Unit_Footman.uasset, L_Arena.umap, pipeline_manifest.json — still dirty, as expected. The Unreal Editor held file locks on the .uasset/.umap files, which made the unlink fail and saved them.
  • INTACTAll Content/RawAssets/ art. These are Git-LFS files; their on-disk mtimes are still the artist's run times and their content matches the commits.

Re-capturing the verify shots needs the editor plus a Simulate pass per unit. It is not done here — it is open item 1 below.
