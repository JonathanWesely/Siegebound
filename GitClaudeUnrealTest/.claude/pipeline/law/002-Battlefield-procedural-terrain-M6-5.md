## Battlefield & procedural terrain (M6.5)
Added 2026-07-10 (TASK-133..137; Jonathan directive: *"start creating the terrain/battlefield the characters fight on … space out the castles … 4 times larger … a grassy terrain filled with rocks, trees, and hills … randomly generated at the start of each match … choose what you think will look best … use as many assets as possible (that still make sense) for variety."*). SUPERSEDES the parked M4.5 hand-placed approach (see the supersede note on that section above). Two parts: **PART 1** = 4× castle spacing (see "World axes (arena contract)" — a level move + a CODE fallback sync, no new assets); **PART 2** = a RUNTIME procedural scatter of trees/rocks/hills/grass, re-seeded each match.

**Fab source assets (READ-ONLY donors, template-donor rule):** Jonathan imported the packs; agents **SOFT-REFERENCE the donor meshes IN PLACE** (never conform/rename/duplicate to fixed `SM_` names — the point is MAX VARIETY cheaply). Known pack roots (art-director browses ALL of them and curates the best-looking, variety-maximizing set): trees `/Game/Tree_Pack_1/Meches/…` (`SM_Highpoly_Tree_1..12` + `SM-Mobile_Tree_1..12` — PREFER the MOBILE low-poly variants for scatter); grass/plants `/Game/Realistic_Grass_and_plant/`, `/Game/Megaplant_Library/`; rocks `/Game/Realistic_Rocks/`, `/Game/Fab/Rocks/highpoly_rocks_free_download/`; hills `/Game/Fab/Stone_Hills_FREE/stone_hill/StaticMeshes/stone_hill`. DO NOT scatter character packs (`Prickly_Knight`, `sA_StylizedWizardSet`), VFX packs, or castle-wall/siege packs (a few siege props from `MedievalCastleEnvironmentAndSiegeWeaponProps` MAY be dressing at the art-director's judgment — flag if used; it is not the core ask).

**Scatter actor:** `ASiegeBattlefieldScatter` (AActor subclass, `BattlefieldScatter.h/.cpp` in `Source/GitClaudeUnrealTest/Siegebound/`), ONE instance placed in `L_Arena` named `BattlefieldScatter`. It owns one **HISM (`UHierarchicalInstancedStaticMeshComponent`) per unique scattered mesh** — instancing is MANDATORY for perf (donor meshes are heavy). Fills the arena at match start via a seeded `FRandomStream`; exposes `GenerateScatter()` / `ClearScatter()`; null-safe (no config = no-op, log once). Log category `LogSiegeTerrain` (one grep-able line with the chosen seed so a layout is reproducible).

**Scatter config (data-driven — density/meshes are content, not code):** `USiegeScatterConfig` (`UDataAsset` subclass, `ScatterConfig.h/.cpp`); instance asset `DA_BattlefieldScatter` at `/Game/Data/DA_BattlefieldScatter`. Holds a per-layer `FScatterLayer` (roughly `{ TArray<TSoftObjectPtr<UStaticMesh>> Meshes; int32 InstanceCount/Density; FVector2D ScaleRange; bool bRandomYaw; bool bBlocking (default FALSE); region-bias; float MinSpacing; }`, programmer picks the exact shape + sane defaults) for the four layers **TREES / ROCKS / HILLS / GRASS**. The actor reads `TObjectPtr<USiegeScatterConfig> ScatterConfig` (EditDefaultsOnly); unset/empty ⇒ graceful no-op. `int32 OverrideSeed` (0 = random each match) + `bool bReRandomizeOnMatchReset` (default true — Play Again gets a fresh layout) live on the actor/config.

**Ground:** the EXISTING arena floor slab is SCALED (build-master) to cover the widened arena and gets a new grass material `M_BattlefieldGround` (Content/Materials/; §6 stylized, macro variation, NO flat single color; MI hue variants allowed in Content/Materials/Instances/). Grass BLADES are a scatter LAYER (HISM), **NOT a UE Landscape** — MCP has no Landscape create/sculpt route (M4.5 ruling 3; a real Landscape would need Jonathan's manual editor work).

**Collision / blocking — BLOCKING obstacles (Jonathan ruling 2026-07-10, decision #1 = the bigger path: rocks/trees/hills physically block unit movement AND carve the navmesh):** obstacle layers (TREES / ROCKS / HILLS) have instances that **block the Pawn channel** and set **`bCanEverAffectNavigation = true`** so they generate nav obstacles; the GRASS layer stays non-blocking decoration (`bBlocking=false`, NoCollision). Instancing choice — HISM-with-nav (preferred for perf; ISM/HISM instances DO support navigation collision) vs individual actors — is the programmer's call, keep the perf budget.
- **Runtime dynamic navmesh is MANDATORY:** `L_Arena`'s `RecastNavMesh` must be `RuntimeGeneration = Dynamic` (project Navigation setting / the nav-mesh actor). Without it, runtime-scattered obstacles do NOT affect pathing and units walk straight through them. Set + verified at TASK-136 (drop a test blocker → confirm the nav carves + a path reroutes).
- **TRAVERSABILITY GUARANTEE (NON-NEGOTIABLE):** the scatter must NEVER wall off a side, trap units, or block a spawn/castle. A match where units cannot reach the enemy castle is a HARD FAILURE. `ASiegeBattlefieldScatter` guarantees a navigable castle-to-castle path EVERY match via: a reserved clear central corridor + the keep-clear radii below, AND/OR a post-placement reachability validation (re-roll / cull offending instances until a Blue-castle → Red-castle path is confirmed).

**Keep-clear zones (manager ruling — decision #3 = YES; now doubly important, it is part of the traversability guarantee):** trees/rocks/hills are excluded from the castle pads (r ~900 around ±8000), gold-node pads (r ~500 around ±7200), the PlayerStart/spawn area, and the central combat corridor (the main lane, |Y| ≤ ~400, that units march along) — so nothing blocks a castle, a spawn, the miner economy, or the lane. GRASS ignores keep-clear (lush everywhere, non-blocking). Radii are config values — Jonathan can make it denser/riskier at playtest.

**Perf (heightened by blocking):** blocking + highpoly + a Dynamic-navmesh rebuild on every scatter is costly. HISM everywhere; prefer the low-poly/mobile mesh variants or LODs; cap per-layer instance counts in the config. The §6 60 fps target is a human WATCH at Jonathan's playtest (no machine stat route — learnings); TASK-137 records best-effort FPS timings and flags if blocking counts must drop.
