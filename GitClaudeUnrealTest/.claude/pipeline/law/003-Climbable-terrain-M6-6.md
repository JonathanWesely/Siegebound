## Climbable terrain (M6.6)
Added 2026-07-14 (TASK-138..145; Jonathan directive: make the battlefield hills/rocks CLIMBABLE by the hero — root-cause investigation established this is BY-DESIGN from M6.5's route-around scatter; **UNPARKS the M4.5 "Gameplay terrain pass" intent**, TASK-091..096). **Root cause of the un-climbable hills:** the scatter applies UNIFORM scale (`BattlefieldScatter.cpp:247`, `FVector(Scale)`), so face angles are SCALE-INVARIANT — scaling the squashed `stone_hill` dome makes it taller AND wider, its flank still goes near-vertical at the rim (a ~4 m unclimbable skirt). No jump buff fixes a dome; the fix is purpose-built CONVEX hill meshes with ≤30° faces + flat crowns, under BOTH the character's 44.76° `WalkableFloorAngle` AND Recast's 44° `AgentMaxSlope`, so hero AND units climb with essentially no movement retune. Four LOCKED decisions (Jonathan, 2026-07-14): (1) M6.5 already committed by Jonathan @ `6a4c17d "battlefield created"` (PUSHED) — GATE 0 satisfied, no build-master M6.5 commit; (2) arena Y widened ±2400 → ±4000; (3) terrain BLOCKS projectiles (arrows die on rocks/hills/tree-trunks — accepted balance change); (4) units climb too (navmesh generates OVER hills — closes the melee-can't-reach-a-crowned-hero exploit). - **Climbable-geometry law (THE gate):** every hill face angle ≤ **30°** (under BOTH the character's 44.76° `WalkableFloorAngle` AND Recast's 44° `AgentMaxSlope` → hero AND units climb, essentially no movement retune); crown near-flat ≤ **8°**; a toe fillet ≥ **120 cm** where the flank meets the ground (NO near-vertical skirt — the `stone_hill` defect); **CONVEX geometry, NO undercuts** (a single hull can't represent concavity — a "ridge" is one stretched dome, never a saddle); ≤ **1200 tris**; **Nanite OFF**; origin at base-center (z_min = 0); UV layer `UVMap`. Collision authored via `generate_convex_collisions(hull_count=1)` — exactly ONE convex hull matching the render mesh (a multi-hull or box hull would re-introduce an unclimbable step). **Acceptance = READBACK, not vibe** (TASK-088/135 technique): report `convexElems == 1`, `hull ZMax == mesh ZMax` (proves the crown is not bulged), and the MEASURED max face-normal-vs-+Z angle (that number is the gate, ≤30°). Material: assign the EXISTING `/Game/Materials/Instances/MI_BattlefieldGround` to slot 0 (world-XY projection → a 27° flank stretches only ~1.12×, so the hill reads continuous with the ground); **NO new material**.

- **`"Terrain"` actor tag on `ASiegeBattlefieldScatter`:** the scatter actor's constructor adds `Tags.Add(FName(TEXT("Terrain")))` — exact string `Terrain` (NOT `Obstacle`). `AProjectile::FindEnvironmentImpact` already object-traces the scatter HISMs and filters by owner-actor tag, so this SINGLE tag closes the projectile pass-through (decision #3: arrows die on rocks/hills/tree-trunks). Regression to hold: a tower on a crown must still shoot units below without its arrows dying on its OWN hill (PIE checklist #7; fallback = drop the tag).

- **Scatter collision-channel law (real geometry vs. proxy):**
  - **Real-geometry blockers (rocks / slabs / hills)** — the HISM blocks `ECC_Pawn` + `ECC_Visibility` + `ECC_Camera` and sets `bFillCollisionUnderneathForNavmesh = true` (Visibility+Camera close projectile pass-through and stop the camera clipping inside a mound when the hero stands on a crown; the nav-underneath fill lets units climb OVER the hill).
  - **Leave `ECC_WorldStatic` on Ignore** — `GroundZAt` (`BattlefieldScatter.cpp:459`) traces WorldStatic for the placement-ghost ground height; blocking it would break placement.

- **Tree collision-proxy contract (invisible-cylinder proxy per visual tree):** a tree's VISUAL HISM carries NO collision — `NoCollision` + `bCanEverAffectNavigation = false`. Blocking is delegated to a PAIRED proxy HISM (exactly one proxy HISM per visual mesh): `SetVisibility(false)` + `SetCastShadow(false)`, `QueryOnly` collision that blocks **Pawn ONLY** (NOT Visibility/Camera — else the placement ghost snaps to the invisible cylinder), `bCanEverAffectNavigation = true` + `bFillCollisionUnderneathForNavmesh = true`. `FScatterLayer` gains `TSoftObjectPtr<UStaticMesh> CollisionProxyMesh`, `FVector CollisionProxyScale = (1,1,1)`, `float CollisionProxyZOffset = 0`; a layer with `CollisionProxyMesh` set uses the proxy system (used for trees: visual canopy + trunk render, an engine `Cylinder` proxy blocks the trunk footprint). The actor keeps a `TMap<UHISM*, UHISM*> VisualToProxy` and MUST cull the visual + proxy HISMs IN PARALLEL (the corridor/keep-clear cull, `CullCorridorBlockers` `:534`, removes from nav-relevant comps = the proxy, and would ORPHAN the visible tree otherwise); register BOTH the visual and proxy HISMs in `ScatterComponents` so `ClearScatter` reaches them.

- **Radius-aware scatter placement (`FScatterLayer::FootprintRadius`):** new `float FootprintRadius` (0 = auto = `FVector2D(Bounds.BoxExtent.X, .Y).Size() * Scale`). Keep-clear (`IsInKeepClear` `:427`, both direct + mirror path `:258`), the field-edge clamp (`|X|+R > HalfX` / `|Y|+R > HalfY`), and radius-aware `MinSpacing` (`DistSq < (MinSpacing+Ri+Rj)^2`) all consume it so a wide hill centered off-lane no longer sprawls across the corridor (the 14–69-culls/seed root cause). ⚠️ Deriving the radius forces the mesh+scale roll to move BEFORE the keep-clear test, which changes the `FRandomStream` draw order — **existing seeds produce NEW layouts** (documented, NOT a regression; a fixed `OverrideSeed` stays deterministic).
