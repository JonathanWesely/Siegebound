## GoldNode / CrystalTower glow materials — as-shipped truth + the emissive brightness lever (2026-07-27)
Added 2026-07-27 (TASK-332/333; Jonathan ruling on the TASK-309 audit: *"dial back the goldnode glow"*). Corrects what the "Textured mesh law → GoldNode emissive economy-prop VARIANT" clause implies is shipping.
- **AS-SHIPPED TRUTH (audit-verified, TASK-309):** `SM_GoldNode` slot 0 carries the hand-authored **`M_GoldGlow`** directly, and `SM_CrystalTower` carries **`MI_CrystalGlow`** — neither uses a `M_AssetPBR` instance and neither samples `T_GoldNode_*` / `T_CrystalTower_*`. **Those baked texture sets are ORPHANED**: they are imported, committed, and referenced by NOTHING on screen. Consequence, recorded so no session wastes credits on it: **a texture re-bake for GoldNode or CrystalTower changes NOTHING visually.** The glow material is the ONLY lever on either asset. The M7 GoldNode-variant clause's `MI_GoldNode_PBR` single-slot option was specced but not the shipped outcome; it is not to be "restored" without a fresh ruling.
- **⚠️ `GlowIntensity` is a RESERVED, RUNTIME-DRIVEN scalar param — it is NOT the brightness lever.** `AGoldNode::UpdateGlowGauge()` creates a lazy MID on slot 0 and writes `GlowIntensity = Lerp(GlowIntensityDepleted 0.05, GlowIntensityFull 1.0, Reserve/InitialReserve)` every gauge tick (the depleting-mine reserve gauge, TASK-253/257). **Therefore the material's authored DEFAULT for `GlowIntensity` is overwritten at runtime and dialling it back is a NO-OP in play.** The param name `GlowIntensity` (exact string, `AGoldNode::GlowIntensityParamName`) must remain a live scalar parameter on `M_GoldGlow` forever — renaming or deleting it silently kills the reserve gauge (the MID write becomes visually inert, no error).
- **The BRIGHTNESS LEVER (law):** dial the **base emissive strength authored INSIDE `M_GoldGlow`** — the value the `GlowIntensity` parameter multiplies — never the parameter default and never the C++ `GlowIntensityFull`. This keeps the gauge's semantics intact (`GlowIntensityFull = 1.0` still means "the authored look", which is simply dimmer now), needs ZERO C++ change, and preserves the depleted-ember floor proportionally.
- **Must survive any glow edit (regression set):** the TASK-257 `GlowIntensity` scalar Multiply, the TASK-226 **0.1 Hz ±12 % sine emissive pulse**, and the TASK-296c "keep-both" superset that merged them. **Stock nodes and parameters only — the Custom-HLSL BAN applies** ("Material & Niagara lane laws").
- **Blow-out acceptance metric (reusable for any emissive asset):** fraction of the mesh rendering past **luma 0.85** in a flat `CaptureAssetImage`, measured the same way for the asset and its reference. Working reference = **CrystalTower 6.5 % blown** (still reads as a crystal). GoldNode shipped at **86.3 % blown** (a featureless cream blob that loses the grey-rock / gold-crystal / orange-crack separation). Target band for a tuned emissive prop: **≤ 15 % blown**, with the concept's material separation legible AND the prop still unmistakably glowing at gameplay camera distance.
