## Findings

- [WARN] concept_generate.py:529,545 — `build_client()` (the `InferenceClient(...)` construction) is called OUTSIDE any try/except in both `run_generate` and `run_all`, so an exception raised *during client construction* would bypass the redactor and be printed by Python's default excepthook. This is the one divergence from the reference standard: in trellis the client construction sits INSIDE the redacting try/except (trellis_generate.py:452-574). Realistic leak risk is negligible — `huggingface_hub`'s `InferenceClient.__init__` does not interpolate the token into any exception message, and a default Python traceback prints source lines + the exception message only, NOT local variable *values* (so the `token=token` kwarg name shows, never its value). The HIGH-risk surface — the actual `text_to_image` network call whose HTTP error body can echo the `Authorization: Bearer hf_…` header — IS fully redacted (line 384) with the exact token value pre-registered in `require_token()` before construction. Suggested fix (parity hardening, not required for correctness): wrap the `build_client` + `generate_one` dispatch in `run_generate`/`run_all` in a `try/except Exception` that routes through `fail()` (redacted), mirroring trellis's redaction envelope.

- [WARN] Board acceptance vs implementation (spec interpretation, not a code defect) — TASK-184 acceptance reads "`--check` passes with the token set and fails cleanly (exit 2) without it," but the implemented `--check` is TOKENLESS by design: it returns 0 whether or not `HF_TOKEN` is set (it only *reports* token presence at lines 489-492, never fails on absence). The exit-2-on-token-unset gate instead lives on the real generation path (`concept_generate.py <CardID>` / `--all` → `require_token()` → return 2, lines 513-515 / 535-537, with clean setup guidance and no token echo). This faithfully MIRRORS `trellis_generate.py`, whose `--check` is *also* tokenless ("must work on a machine with no HF_TOKEN set", trellis:349-355) — and the spec explicitly names trellis as the authoritative mirror. The exit-2 behavior IS present and correct on the generation path. Flagging only so the manager can confirm the interpretation; recommend NO change (matching the reference standard is the stronger constraint). If the manager rules `--check` itself must exit 2 without a token, that would DIVERGE from trellis and should be applied to both tools.

- [NIT] concept_generate.py:97,146-151,316 — dead code carried over from mirroring trellis: `DEFAULT_SEED` (unused; CLI `--seed` defaults to `None`), the `ApiDriftError`/`QuotaExceededError` classes (defined but never raised — concept classifies via `_looks_like_*` + direct return codes and writes no state file), and `_utc_now()` (unused — concept writes no provenance JSON). Harmless; optional cleanup.

- [NIT] concept_generate.py:355 — `if args.steps is not None` is effectively dead (`--steps` defaults to `DEFAULT_STEPS`, never `None` via the CLI). Harmless; a swap-seam convenience only.
