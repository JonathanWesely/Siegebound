**Cycles: structurally impossible, and the header's argument is sound.** Each `UUserWidget` owns a distinct
`UWidgetTree`; `ForEachWidget` descends only from `RootWidget` through `UPanelWidget` children and named slots, so
a cycle would require a widget to be its own ancestor. Depth cap is belt-and-braces. **Non-termination is not
reachable.**

**Visited set: NO — and this is where the row's own discovery doubles back on it.**

⚠️ **WARN-1 — the named-slot correction creates a DUPLICATE-VISIT path the row established the premises for and
did not follow through.** Verified at engine source:

- `ForWidgetAndChildren` enters the `INamedSlotInterface` limb on every widget (`WidgetTree.cpp:246-263`), and
  `class UUserWidget : public UWidget, public INamedSlotInterface` (`UserWidget.h:280`) — the row's §2 correction,
  confirmed.
- `UUserWidget::InitializeNamedSlots` (`UserWidget.cpp:204-226`) inserts `Binding.Content` **as a child of the
  `UNamedSlot` inside the sub-widget's OWN `WidgetTree`** — and **does not clear `NamedSlotBindings`**.
  `GetContentForSlot` (`:1284-1295`) keeps returning the same pointer afterwards.

⇒ For a **native** nested user widget carrying a named slot with injected content, the same content subtree is
now reached **twice**: once by the outer walk's named-slot limb, once by this row's descent into that widget's
tree. `OutStops` has no `AddUnique` and no visited set ⇒ **duplicate stops**. That is not a cycle — the header's
*"a widget tree cannot contain itself, so this cannot cycle"* is true and simply silent about revisits. A
duplicated stop in a ring indexed by `Find`/`IndexOfByKey` short-circuits the ring at the first occurrence.

**Why this is a WARN and not a BLOCKER:** it cannot fire today. This project authors **zero** `UNamedSlot`s — I
re-ran the `Source/` half of that census myself (every textual hit is a comment; nothing constructs one). The
zero-`UNamedSlot` measurement is therefore load-bearing for **two** things, and the row only wrote down one of
them. A one-word `AddUnique`, or one sentence at the descent naming the duplicate case, closes it.

(A secondary, same-root ordering note: with a named slot present, the interior stops would be emitted **before**
the injected slot content, so the "strict superset with nothing permuted" property is also conditional on the

**What produces `47+`:** 13 + the 34 design-time `Btn_Jump`s (one per tile, verified at the asset). Nothing
