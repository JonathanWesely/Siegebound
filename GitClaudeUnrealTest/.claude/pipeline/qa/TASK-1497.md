## RULING ON THE RESIDUAL IT DELIBERATELY LEFT — header `:1054`

`h:1054` reads *"THE FOCUSABLE SET GREW FROM ONE BUTTON TO `RowWidgets.Num()` + 2"*. I checked the arithmetic
rather than the story: the whole tree's focusable set is N `RowButton`s + `CloseButton` + `BackButton` = **N + 2**.
That is **true as the file now stands**. Under `TASK-1484` it was N + 3 and the line was **false for that
feature's entire shipped life**.

**Ruling: leaving it is correct.** A true comment needs no edit; amending it would widen a removal row into
a file it has no reason to touch, and the row flagged it instead of silently touching it — which is the
behaviour the board wants. No finding against `TASK-1496`.

**But the fact underneath it is worth more than the line itself, and it is recorded here for the manager:**
a count comment was **false for the whole lifetime of a shipped feature and three gates did not catch it —
two of them mine.** It survived because it is *prose about a number*, not a number a compiler, a test or a
grep for a symbol can reach; every gate in this wave read what changed, and this line's defect was that it
**did not** change. A gate that reads a diff cannot see a sentence that should have been in it. The general
form: **a removal or an addition that alters a tally obliges an author to re-read every comment that states
that tally, and no tool we run enumerates those.** The recovery here was luck — a second edit restored the
truth value — and luck is not a control. Worth one line in `TASK-1480`'s scope: annotate `h:1054` with its
round-trip (true at `TASK-1478` → false through `TASK-1484` → true again at `TASK-1496`) so a reader cannot
mistake a coincidence for a maintained fact.
