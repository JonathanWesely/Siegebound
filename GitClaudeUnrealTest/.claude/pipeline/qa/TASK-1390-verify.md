## Hypotheses (not verdicts)

- **H1 (the mechanism, and the strongest one available).** The invariant across all four shapes is not that the pointer missed — it is **`up handled=false` while `down handled=true`**. A real Slate click completes only if the widget that handled the down holds **mouse capture** when the up arrives; `SButton::OnMouseButtonUp` returns unhandled and skips `ExecuteOnClick` when it is not the capturing widget. ⇒ **the synthesised down is delivered and accepted, but the capture that must accompany it is not established, so the up is never recognised as completing a click.** Consistent with every trace, and with the identical `1.0.5` signature. ⛔ **MECHANISM NOT MEASURED** — no Slate-internal state (`HasMouseCapture`, the capture path) is readable by any tool on this agent's line, and no engine source was read to confirm the code path. This is the leading suspect, and it stays a hypothesis (`SC-§101`).
- **H2 (why the earlier "TextBlock swallowed it" story is dead).** It was the obvious reading of L1/L2's `hit_widget: "STextBlock"`, and L3 killed it — see §C. Recorded because it is exactly the tidy explanation a later reader would re-derive and act on.
