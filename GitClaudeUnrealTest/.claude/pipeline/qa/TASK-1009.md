## §4 — ⚖️⚖️ THE JUDGEMENT CALL: **QUOTE vs DESCRIBE** — RULED

**The two genuinely cannot both stand, and I verified that rather than accepting it.** `CountOccurrencesAnywhere` (`SiegeFogReachSeamTest.cpp:154-175`) is a raw substring count over the whole file, comments included. If the repaired block **quoted** `TEXT("TODAY THIS RETURNS FALSE")`, that probe returns ≥1 and **test 4 cannot pass while the retirement is documented**. The dichotomy is real.

### ⚖️ **RULING: DESCRIBE, NOT QUOTE — the author's rule is UPHELD, with one binding rider.**

**Why, said plainly rather than left implied:**

1. **The record is not actually lost — it moved to where records belong.** The *"describing loses the exact wording"* half of the trade is only true if the source is the only ledger. It is not. `SiegeCombatStatics.h` is a **tracked file**, so all three retired sentences are preserved **verbatim and forever in git history**, and `handoffs/TASK-1007-programmer.md` §4(a) carries identifying fragments of each. ⇒ this project's *"records being lost"* burn is **not incurred here**. The *"stale prose surviving unseen"* burn **would** be incurred by the other choice, because the probe would have to be deleted or weakened to ship.

2. **The two failure modes are not symmetric in cost.** A lost exact wording costs a future reader one `git log -p`. A blinded probe costs the project a **repeat of the defect that created this row** — and this batch has already paid for that repeat twice (`CardRow.h` 3→8, `SiegeFogClampTest.cpp` 3→4: every stale-claim count rose when a fresh reader looked, because nothing red was watching).

3. **A quoted retirement is genuinely indistinguishable from a live claim — to a scanner AND, at a glance, to a human.** A reader skimming a doc block sees the sentence. The blockquote convention that separates them for a human does not exist for a substring search, and a probe that has to parse "is this inside a retirement block?" is a parser, and the house rule is explicitly that these helpers are **not parsers** (`SC-§38`).

4. **The needles chosen make the cost small.** All three (`TASK-839 is BLOCKED BY THIS TASK`, `WHAT TASK-839 DOES WITH IT`, `TODAY THIS RETURNS FALSE`) are **future-framed ownership clauses** — the shape that actually went false — not general fog vocabulary. Collision risk with a legitimate future sentence is low, and a collision goes **red and gets argued**, which is the correct direction to fail.

**⛔ THE BINDING RIDER (this is what makes the ruling a resolution rather than a coin flip), proposed as standing practice:**

> ***The SOURCE describes; the HANDOFF quotes; GIT is the ledger.*** A row retiring a false sentence must reproduce it **verbatim in its handoff** (so the record survives outside a diff) and **must not** reproduce it in the source (so the probe stays sharp). Neither half is optional: describe-only-with-no-handoff-quote **is** the records-lost failure, and it is the one to watch for next time.

⚠️ **Residual, named:** `handoffs/TASK-1007-programmer.md` §4(a)'s quotes are **elided** (`"…"`), not full. Under the rider that is a shortfall, mitigated to acceptable by the file being tracked so git holds the full text. **NIT N-3-adjacent; no action demanded of this row.**

⛔ **The author's own contrary option is therefore CLOSED:** if a future row prefers the quoting idiom, it must first move `SiegeFogReachSeamTest.cpp` test 4's needles — **and it may not do both.**
