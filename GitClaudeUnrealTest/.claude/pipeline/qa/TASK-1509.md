## Point-by-point (the dispatch's five, and row `TASK-1509`'s five BLOCKER criteria)

### Point 1 — the bar-walk relay: re-entrancy, loops, edge cases, user index, real-key invariance

**Can the synthesized key reach Enhanced Input and re-fire `IA_MenuLeft/Right`? Key-down: no. Key-up: it can reach the viewport client, but it cannot re-fire.**

Key-down, traced:
- `ProcessKeyDownEvent` (SlateApplication.cpp:4961-5076) tunnels `OnPreviewKeyDown` root→leaf over the user's focus path. `SViewport` has **no** `OnPreviewKeyDown` (SViewport.h:230-231 declares only `OnKeyDown`/`OnKeyUp`).
- The tunnel reaches the builder's `NativeOnPreviewKeyDown` → `HandleCardGridKey(Left)`: grid not live, not `Down`, `IsDeckBarActivationKey(Left)` false ⇒ `Unhandled`.
- The bubble then starts at the focused `SButton`. `SButton::OnKeyDown` is not Accept for Left/Right → `SBorder`/`SWidget::OnKeyDown` (SWidget.cpp:416-429): `bCanSupportFocus && SupportsKeyboardFocus()`, where `SButton::SupportsKeyboardFocus` returns `bIsFocusable`, default true, and `UDeckSlotEntryWidget` never clears it. Result: `Handled().SetNavigation(...)`. The bubble stops before `SViewport`.
- **A second backstop the handoff did not cite:** if the `SlotButton` were ever disabled (the bubble lambda skips `!IsEnabled()`), the event continues up. It passes the entry (root not focusable, `Unhandled`) to the **builder root**. `SObjectWidget::OnKeyDown` (SObjectWidget.cpp:231-245) calls `NativeOnKeyDown` and then falls through to `SCompoundWidget::OnKeyDown`. The builder is focusable (`SetIsFocusable(true)`, DeckBuilderWidget.cpp:1534), so it too returns a navigation `Handled`.
- The relay only runs when a bar slot holds focus, so the builder is necessarily on the path. The down event cannot reach `SViewport` in any enabled/disabled combination.

Key-up: see N1. The Released edge is closed by `IgnoreInput` on `L_MainMenu`, and `Started`-only bindings cannot fire on it anywhere.

**Recursion:** `UPlayerInput::InputKey` only records key state, and action delegates evaluate in the next `ProcessInputStack`. There is no synchronous path from the relay back into `RouteMenuNavKey`.

**Edge cases:**
- **Disabled slot:** 0 `SetIsEnabled` / `IsFocusable` / `SetNavigation` calls in `DeckSlotEntryWidget.cpp` (grep). Even hypothetically, the builder-root backstop above applies.
- **Focus lost mid-relay:** `ProcessReply` runs the navigation synchronously (SlateApplication.cpp:3650-3697, `AttemptNavigation`), so `SlotAfter` reads the real landing. If Slate moves focus off the bar, `SlotAfter = INDEX_NONE` and `MakeFixedDeckName(INDEX_NONE)` returns `""` by contract (SiegeDeckSaveGame.cpp:17-22). No crash. The key-up then goes to the new focus holder, exactly as a physical key-up would.
- **No Slate user:** `GetOrCreateUser(InKeyEvent)` creates it. `FSlateApplication::IsInitialized()` is guarded. A null PC or `LocalPlayer` returns false → the shipped call. All pointers are checked.
- **Ends of the bar:** Slate's own `OnNavigation` walk plus `AttemptNavigation` from the leaf. Same answer as a physical arrow; reported, not corrected.
- **Non-nav key:** the `Warning` path cannot fire for `Left`/`Right` under the default config. `NavigationConfig.cpp:19-23` maps both, and there are 0 `SetNavigationConfig` calls in the project.
- **Input preprocessors:** there is no `RegisterInputPreProcessor` / `IInputProcessor` / `SetUnhandledKeyDownEventHandler` anywhere in the project (`Source/` + project `Plugins/`, grep). Aura's, if any, are declared unexamined by the programmer and by me.

**User index:** `GetUserIndexForController(LocalPlayer->GetControllerId())` returns `int32` (SlateApplication.h:1822, public, not deprecated). A physical key uses `GetUserIndexForKeyboard()` (SlateApplication.cpp:4956). Under the default mapping both are 0 for local player 0. It is the same user the builder's existing focus calls address (4 prior sites in this file). Residual multi-user gap: N2.

- (a) For `Key ∈ {Left, Right}`, `HandleCardGridKey(const FKey&)` returns what it returned before, in every state. The only new code (`:1813-1821`) is gated on `IsDeckBarActivationKey(Key)`, false for both, and sits after the directional block.
