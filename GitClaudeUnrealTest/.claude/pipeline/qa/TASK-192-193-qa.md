- **[BLOCKER — FIXED IN LOOP 1] refine_trellis_glb.py:694–699 (`resolve_delight_config`) — per-key

  `try/except (TypeError, ValueError)` → warning + that key's default.
- [WARN — FIXED IN LOOP 1] `cfg["enabled"] = bool(cfg["enabled"])`: a JSON string `"false"` is
  truthy, so `{"enabled": "false"}` silently keeps the step ON. Accept strict bool only.

  any FUTURE native-mode rerun of a previously shipped asset produces a slightly brighter D by

### (1) BLOCKER — CLEARED

`sanitized_number(key, lo, hi)` helper (lines 706–728) replaces every bare `float()` coercion
(call sites 730–735):

- All three loop-0 repros now warn-and-default with zero exceptions:
  `{"gamma": null}` → `float(None)` TypeError caught; `{"gamma": "bright"}` → ValueError caught;
  `{"ao_floor": [0.35]}` → TypeError caught — each appends exactly ONE `report["warnings"]` entry
  and falls back to that key's `ALBEDO_DELIGHT_DEFAULTS` value, then range-clamps.
- **Hardening 1 (bool-for-numeric) correct:** `isinstance(value, bool)` is checked BEFORE the float
  coercion — required ordering, since bool is an int subclass and `float(True)` would silently
  coerce to 1.0.
- **Hardening 2 (non-finite) correct and necessary:** `math.isfinite` runs post-coercion.
  Python's `json.load` does admit `NaN`/`Infinity` literals by default, and NaN genuinely survives
  `min`/`max` clamping (NaN comparisons are False, so `min(max(nan, lo), hi)` returns NaN) — without
  this check a manifest NaN would poison the whole image math. String forms (`"nan"`, `"inf"`) that
  pass `float()` are also caught here. `math` is a pre-existing import (line 103) — still no new
  imports.
- **No raise path remains:** defaults are finite numeric literals (`float(default)` safe), `!r` in
  the warning f-strings is safe for arbitrary values, and the final `float(min(max(value, lo), hi))`
  operates on guaranteed-finite floats. Sanitize order preserved: `max_out` before `shoulder`, so
  shoulder's hi bound (`cfg["max_out"] - 0.01` ∈ [0.49, 0.99]) stays valid and the soft-shoulder
  denominator stays > 0. A config value can no longer fail the run at ANY point — the loop-0
  early-resolve suggestion is indeed moot, as the handoff argues.

### (2) WARN (strict-bool `enabled`) — CLEARED

Lines 700–704: `isinstance(cfg["enabled"], bool)` gate — `{"enabled": "false"}` and
`{"enabled": 1}` now warn + use the default instead of silently staying ON (`isinstance(1, bool)`

the container-bool form (`"albedo_delight": false`) and the object form (`{"enabled": false}`).
Note the warned-bad-value outcome is default-ON with a surfaced warning — exactly the warn+default

### (3) NIT (alpha mirror) — CLEARED

Lines 796–801: `has_alpha = int(getattr(img_d, "depth", 0)) in (32, 64, 128)` →
`bpy.data.images.new(..., alpha=has_alpha, ...)`. Depth mapping is correct for RGBA layouts
(byte 32 / 16-bit 64 / float 128); a native-mode D carrying alpha now keeps it in the written PNG
(the copied source alpha values were already preserved in `out_rgba`). **Bake-mode bit-identical
behavior CONFIRMED:** the bake D is byte RGB (depth 24, `_new_bake_image` alpha=False) →
`has_alpha=False` → the `images.new` call is argument-identical to the first submission. The
`getattr(..., 0)` fallback fails safe (no alpha). `foreach_set` length is unaffected either way
(pixel buffers are always RGBA).
