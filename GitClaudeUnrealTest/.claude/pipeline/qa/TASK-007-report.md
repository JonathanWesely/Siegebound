## Rulings on the programmer's three flagged concerns

1. **LMB polling in PlayerTick + ProcessEvent-by-name SetWinner — ACCEPTED as safe.** (a) Polling `WasInputKeyJustPressed(EKeys::LeftMouseButton)` after `Super::PlayerTick` is legal, frame-correct, and justified: `AttackAction` is protected on QA-passed HeroCharacter.h, and the double-fire is neutralized by melee suppression (verified: `DoMeleeAttack` no-ops without consuming cooldown, HeroCharacter.cpp:128). (b) The `ParmsSize == sizeof(ETeamId)` guard (cpp:350) IS sufficient for memory safety: ProcessEvent copies exactly ParmsSize (1) bytes from the 1-byte local, and any out/return copy-back writes at most 1 byte back into it — no signature can cause an out-of-bounds read/write. The residual risk is purely semantic (a 1-byte bool/byte/other-enum param would silently receive the winner byte) — see WARN-1.
2. **Castle-roof placement at X <= 0 — ACCEPTED for M1.** Any Visibility-blocking surface on the Blue half is placeable (cpp:505, 609-615); the Blue castle roof qualifies. Worst case: 3 gold buys a unit with no navmesh under it that idles and retries (TASK-004 behavior) — self-inflicted, non-crashing, outside M1 acceptance. Must be fixed with M2 placement rules (see WARN-2).
3. **GameAndUI drag nudging the camera — COSMETIC, accepted.** Only occurs while LMB is held during capture; confirm fires on just-pressed so a normal click never shows it. See NIT-1 for a one-line polish option.

## Findings

- **[WARN] SiegePlayerController.cpp:350** — `ParmsSize == sizeof(ETeamId)` accepts any 1-byte signature (single bool/byte/foreign-enum param, or a param-less function returning bool), silently mis-feeding or mis-reading the winner. Memory-safe, so not a blocker, but cheap to harden: additionally require `SetWinnerFunction->NumParms == 1` and that the single `CPF_Parm` property is an `FEnumProperty`/`FByteProperty` whose `GetEnum() == StaticEnum<ETeamId>()` and is not `CPF_OutParm|CPF_ReturnParm`. Alternatively fold into the next touch; TASK-011 MUST implement `SetWinner` with exactly one ETeamId input per the handoff contract.
- **[WARN] SiegePlayerController.cpp:505, 609-615** — validity is "any Visibility-blocking surface at X <= 0": Blue castle roof/walls are placeable and can strand a paid unit off-navmesh. Accepted for M1 (ruling 2). TODO(M2) when placement rules land: project the hit point to navmesh (`UNavigationSystemV1::ProjectPointToNavigation`) as part of validity.
- **[WARN] SiegePlayerController.cpp:386-394** — `HandleMatchEnd` switches to `FInputModeUIOnly` even when `VictoryWidget` is null (WBP_VictoryScreen missing, pre-TASK-011): no UI exists to click and no game input remains — a soft-lock in the degraded state. Suggest applying UIOnly only when the widget was created (else keep GameAndUI + cursor so the session stays inspectable). Not a blocker: it cannot occur once TASK-011 ships, it is logged, and it does not crash.

- **[NIT] SiegePlayerController.cpp:259-266** — the dead-hero refusal logs but does not broadcast `OnCardPlayRefused`, unlike every other player-facing refusal; the HUD would flash nothing. One-line consistency fix on next touch.
- **[NIT] SiegePlayerController.cpp:132** — polled `EKeys::Escape` is consumed by the editor in PIE (ends the session); RMB and IA_CancelPlace cover cancel there. Works in packaged builds. Playtest note only.
