## Findings

- **[WARN-1] SiegeBotController.cpp:164-:184 / :604 — rule-5 spell exemption accelerates a pre-existing idle-player hand-clog.** Worst case vs a fully passive player: the hand converges to 6 cards the bot will never play *in that scenario* — non-economy Buildings only play under rule 1 (needs an intruder; deck holds 11 such cards: ArrowTower 2, Wall 2, BombTower 2, Ballista 2, Barracks 2, CrystalTower 1), Miner cards stall once the alive-miner target holds, and now Fireball×2/Lightning×2 join the held set (no cluster / no player tower ever appears). Bot then goes fully inert (no plays, no discards) and the GDD "progressively larger waves while idle" acceptance degrades in long idle matches. Ruling: NOT a blocker — the failure class predates TASK-102 (M4-accepted building/miner behavior), it cannot crash or corrupt state, and the added exemption follows the spec's own discard-clause wording. **Carry-forward:** playtest watch at TASK-109; suggest a future balance task exempting only the FIRST copy of each castable spell (or a hold-timeout) — cheap hardening, manager's call.
- **[WARN-2] SiegeBotController.cpp:475-:476, :746-:753 — centroid cast can leave outlier cluster members outside the actual blast.** Members are within R of the ANCHOR; the centroid can sit up to ~R from a member's opposite edge (example: units at (0,0),(R,0),(R,0),(−R,0) → centroid (R/4,0); the (−R,0) unit is 1.25R from the cast point). The algorithm is exactly what the spec mandates (anchor-defined cluster, centroid cast), so this is spec-inherent, not a code error — but the comment "the bot only casts when the found targets actually fit inside the real blast" overstates, and the trace's "N player units within R" counts the cluster, not guaranteed blast victims. Ruling: accepted as spec-conformant; soften the comment at next touch; playtest watch (Fireball may occasionally hit N−1).
- **[NIT-1] SiegeBotController.cpp:472 — rule 3 nested inside `if (UWorld* World = GetWorld())`:** in a null-world degenerate state rule 3 silently skips while rules 4/5 still evaluate (they'd fail their own world checks downstream). Harmless asymmetry; a null world here is unreachable in practice (timer requires a world).
- **[NIT-2] SiegeBotController.cpp:500/:543 — on the unreachable SpendGold-false tripwire the trace line still prints `gold G->G` (unchanged),** cosmetically recording a zero-cost play. Acceptable: the Warning tripwire on LogGitClaudeUnrealTest adjacent to it disambiguates.
- **[NIT-3] SiegeBotController.h:143-:152 — header doc for rule 3 is excellent, but says "casts resolve DIRECTLY through USpellLibrary::ResolveSpell" without noting the resolve-then-SpendGold ordering** that the cpp comment (cpp:464-:471) documents; consider mirroring one sentence at next touch.
