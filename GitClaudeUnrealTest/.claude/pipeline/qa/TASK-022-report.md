## Rulings on the 14 flagged decisions (handoffs/TASK-022.md)

1. **Eager reshuffle** — **PASS.** The spec's preview law ("must always be the ACTUAL next draw") is genuinely unsatisfiable with lazy reshuffle from a const Peek; eager is the only design that keeps PeekNextCardID const, truthful, and allocation-free. Invariant proof verified (summary 2). The pile-count jump is physically correct and invisible (no HUD element shows pile counts in §7).
2. **Two piles + hand (not three)** — **PASS.** GDD §3.4 (the spec's own authority) defines exactly two piles — draw and discard — plus the hand; the board's "three piles" is a slip or counts the hand. No behavior in the spec needs a third container, and skipping a cached "built deck" list in favor of re-reading the table on reset is strictly better (a TASK-031 reimport takes effect on the next Play Again without restarting PIE).
3. **bool returns on ConfirmPlayFromHand/DiscardFromHand** — **PASS.** Spec is silent on returns; the names block pins names, not signatures. The bool is the no-cost refusal signal that lets TASK-023 close the WARN-2 discard gold leak (see WARN-1); BlueprintCallable ignores output pins freely, so written call sites that discard the value still work.
4. **GetHandSize() added** — **PASS.** Additive-only BlueprintPure; keeps TASK-029's slot loop in sync with the single source of truth instead of double-hardcoding 6. Precedented (TASK-018 QA accepted spec-adjacent additive getters).
5. **HandSize=6 / ExpectedDeckSize=50 as EditDefaultsOnly UPROPERTYs** — **PASS.** This is the CONVENTIONS mechanic-rule registry treatment verbatim ("hand of 6", "a deck is exactly 50 cards" are rules, not CSV columns — same as miner cap 6), with GDD §3.4 citations in the comments and ClampMin=1 guards. ExpectedDeckSize used only for the error log; build always proceeds.
6. **One OnDeckHandChanged per mutation (deal fires once, not six)** — **PASS.** The payload-less delegate the spec itself defined implies coarse refresh semantics (consumers re-read all slots); six identical refreshes per deal would be pure waste. "Whenever any hand slot changes" is satisfied — every mutation that changes any slot fires exactly one broadcast.
7. **Value-filtered preview + forced on build/reset** — **PASS.** Direct application of the CONVENTIONS delegate law ("every ACTUAL value change and on reset paths"). The consequence — the hand delegate, not the preview delegate, is the per-draw heartbeat — is correctly documented for TASK-029 in both the handoff and the header comment. Filter-cache (LastPreviewCardID) can never go stale: it is updated on every broadcast and every preview change routes through BroadcastPreview.
8. **Discard-first-then-draw ordering** — **PASS.** Matches GDD §3.4's physical-card rule (the played card is in the discard when the reshuffle its replacement draw triggers happens); with the real 50-card deck the ordering is unobservable; with degenerate decks it is the correct behavior (single-card deck cycles instead of dying — traced).
9. **Refused mutations: Warning + false + no state change + no broadcast** — **PASS.** CONVENTIONS law verbatim ("never broadcast refused/ignored mutations"). The empty-slot Warning during the WARN-2 window is user-action-bounded (per keypress, never per tick) and is the diagnostic breadcrumb — keep it.
10. **Log severities (Error for missing table and total != 50)** — **PASS.** "Log an error" is the spec's literal word for the total mismatch; for the missing table, the deviation from M1's missing-asset Warning convention is justified — DT_Cards has existed since TASK-008, so a miss is a real fault, not a parallel-dev gap. The 0-card Error's embedded pointer to WARN-2/TASK-031 makes the known window self-diagnosing in the PIE log. Exactly once per build.
11. **Negative DeckCount clamped to 0 with Warning** — **PASS.** Pure defense-in-depth; TASK-021's audited data has none; per-row Warning is proportionate.
12. **No BeginPlay / no self-initialization** — **PASS.** TASK-023's spec explicitly owns the BuildAndShuffle timing ("call BuildAndShuffle at match start and ResetDeck from the PlayAgain flow"); self-building at BeginPlay would race it. Pre-build calls are safe (getters return NAME_None, mutations refuse) — verified.
13. **Piles/hand as VisibleInstanceOnly + Transient UPROPERTYs** — **PASS.** Live-inspectable for the TASK-040 PIE verification, never serialized into the BP or level; LastPreviewCardID as a plain FName member is correct (pure cache, value type, GC-irrelevant). See NIT-2 (redundant AllowPrivateAccess meta).
14. **Hand-rolled Fisher-Yates over FMath::RandRange** — **PASS.** Algorithm verified unbiased with inclusive-bounds RandRange (engine header checked); pre-compile reviewability rationale is sound and the RNG source is pinned explicitly. See NIT-1 for the (non-blocking) determinism note.
